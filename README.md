# 🇷🇸 SrpskiLab 2.1

Многопользовательский учебный сайт: курс сербского A0–B2, регистрация, серверные зачёты, последовательная разблокировка уроков, словарь, карточки, экзамены и сербское аудио.

> **Важно о готовности.** Все файлы приложения, 265 уроков, SQL-миграции, серверные RPC, 1 235 аудиозаписей и код удаления аккаунта включены. **Созданного Supabase-проекта, действующих ключей, настроенного SMTP и реального развёртывания здесь нет** — это нужно выполнить владельцу. Аудиофайлы сгенерированы локальным голосом eSpeak `sr`; они синтетические и требуют проверки произношения перед официальным выпуском всего курса. В исходном контенте A1–B2 много повторяющихся модульных материалов; 265 записей — не 265 выверенных авторских сценариев. Не объявляйте полный педагогический аудит завершённым.

## 1. Что внутри

- **Frontend:** React 19 + TypeScript + Vite, React Router, собственная адаптивная CSS-система.
- **Учётные записи:** Supabase Auth email/password, подтверждение почты, восстановление, выход, смена пароля.
- **Хранилище:** Supabase PostgreSQL, RLS. Серверная проверка уроков/экзаменов в SQL RPC, клиентский балл не принимается как результат.
- **Курс:** 31 модуль / 265 записей уроков, словарь **714** уникальных записей, 7 проверочных заданий в уроке и 20 вопросов в экзамене.
- **Ограничения:** урок 1 доступен новичку; урок N+1 только после подтверждённого результата урока N (>=70%); следующий уровень после экзамена предыдущего (>=80%).
- **Аудио:** 1 235 сербских MP3, динамик возле слов, ключевых фраз и реплик; управление скоростью/паузой; системный сербский голос — только резерв.
- **Прогресс:** сохранение в облаке, история попыток, лучшая оценка, словарь и SRS 1/3/7/14/30 дней, повторные тесты не отменяют старые зачёты.
- **Нет сети:** неотправленная попытка урока попадает в локальную очередь IndexedDB текущего аккаунта; **не объявляется зачтённой до ответа сервера**.
- **Перенос старых данных:** импорт JSON версии 1 с сохранением истории, старых экзаменов, словаря, карточек, ошибок и событий как архив; уроки из старого JSON без подписи **не считаются серверно проверенными**, чтобы импортом нельзя было открывать любые занятия.
- **Удаление аккаунта:** код защищённой Edge Function, требуется отдельно опубликовать её в Supabase.

## 2. Запуск на компьютере в Visual Studio Code (Windows)

1. Распакуй архив проекта, открой папку целиком через **File → Open Folder** в VS Code.
2. Убедись, что установлена актуальная Node.js LTS (22+) и npm.
3. Открой встроенный терминал **Terminal → New Terminal**.
4. Выполни:

   ```powershell
   npm install
   Copy-Item .env.example .env.local
   ```

5. Создай бесплатный Supabase-проект: https://supabase.com/dashboard/projects. В **Project Settings → API** возьми URL проекта и **publishable key** (или публичный `anon` ключ, если он используется в проекте).
6. Открой `.env.local` и впиши **свои** значения:

   ```env
   VITE_SUPABASE_URL=https://ТВОЙ-ПРОЕКТ.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_... 
   ```

   Не добавляй туда `service_role`, SMTP, Azure/Google API ключи. Файл `.env.local` исключён из Git.
7. **Выполни SQL-миграции последовательно** через Supabase → SQL Editor:
   - `supabase/migrations/202609290001_schema.sql` — таблицы, RLS и серверные функции;
   - `supabase/migrations/202609290002_seed.sql` — реестр уроков и словарь. **Закрытый банк ответов исходный seed не заполняет**, его состояние необходимо проверить отдельно по `docs/course-v3/MANUAL-SETUP-RU.md`.
8. В Supabase → Authentication → Providers включи **Email**. В Auth → URL Configuration укажи `Site URL`: `http://localhost:5173`, добавь разрешённые `Redirect URLs` для `http://localhost:5173/**`, а после публикации — адрес на Vercel и URL восстановления пароля.
9. Выполни:

   ```powershell
   npm run dev
   ```

   Открой **http://localhost:5173**.
10. Зарегистрируй первый тестовый аккаунт. Если включено подтверждение почты, подтверди адрес через письмо. Проверь загрузку профиля и прохождение первого урока. Для *production* настрой отдельный SMTP в Supabase — встроенная тестовая отправка почты ограничена. Также проверь два `private.*_question_bank`: из базового seed они не заполняются. Диагностика и безопасное восстановление оригинального банка — `docs/course-v3/MANUAL-SETUP-RU.md`.

### Ошибка «Could not find the table ...»
Не применены SQL-миграции или указаны ключи другого проекта Supabase. Выполни миграции именно в базе, URL которой внесён в `.env.local`.

### Ошибка «permission denied» / пустая статистика
Убедись, что включена сессия Supabase и выполнена схема с RLS. Не отключай RLS ради обхода ошибки: найди проблему по журналу запросов.

### Кнопка регистрации недоступна
Если `.env.local` пустой, откроется экран первого запуска. После изменения env-файла перезапусти `npm run dev`.

## 3. Опубликовать сайт на GitHub из VS Code

**Не удаляй старый сайт до создания резервной копии.** Создай отдельную ветку (`feature/srpskilab-2`) в исходном репозитории `Strannuk87/SrpskiLab` либо создай новый репозиторий. Затем копируй все файлы **кроме** `node_modules`, `.env.local` и `dist`.

В Source Control (иконка Git слева) проверь список изменений, нажми **Stage All Changes**, напиши `feat: SrpskiLab 2.1 cloud learning` и нажми **Commit**, затем **Publish Branch / Push**. Рекомендуется PR и просмотр diff перед слиянием в `main`. Если в папке ещё нет Git, выполни в терминале `git init`, `git remote add origin https://github.com/Strannuk87/SrpskiLab.git`, затем создай ветку или используй VS Code для входа в GitHub. Не выполняй `git push --force` по существующей ветке.

## 4. Опубликовать на Vercel

1. Vercel → **Add New → Project** → импорт репозитория `SrpskiLab`.
2. **Framework: Vite**; Build Command: `npm run build`; Output Directory: `dist`; Install Command: `npm install` (или оставить автоматическую установку).
3. В **Environment Variables** добавь `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` с публичными значениями **из того же Supabase проекта**.
4. Выполни Deploy. Vercel выдаст адрес вида `https://имя.vercel.app`.
5. В Supabase → Authentication → URL Configuration выстави production `Site URL` и добавь `https://твой-домен.vercel.app/**` в allow-list перенаправлений. Проверь подтверждение email, восстановление и переход напрямую на `/lesson/m1l1` после F5.
6. Настрой production SMTP (или другой совместимый почтовый провайдер), а также политику резервного копирования и восстановления БД.
7. **Не включай публичную регистрацию**, пока не проверены RLS двух пользователей, вход, удаление, доставляемость писем и лицензионная пригодность аудио.

Файл `vercel.json` уже содержит SPA rewrite. Корень репозитория — корень сборки, не выбирай старую `legacy/site` как Root Directory.

## 5. Реальное удаление аккаунта

Кнопка удаления требует публикации Edge Function. Установи CLI и залогинься в своём Supabase-проекте:

```powershell
npx supabase login
npx supabase link --project-ref ТВОЙ_PROJECT_REF
npx supabase functions deploy delete-account
```

Функция находится в `supabase/functions/delete-account/index.ts`. В своей серверной среде Supabase должны быть доступны `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`. **Никогда** не переноси служебный ключ в JS frontend и не публикуй его на GitHub. После деплоя проверь удаление на *тестовом* аккаунте. Удаление `auth.users` каскадно удаляет личные записи по внешним ключам.

## 6. Аудио

В `public/audio/` лежат 1 235 MP3, сгенерированные движком **eSpeak** с выбранным сербским голосом `sr` и экавским материалом. `public/audio/manifest.json` сопоставляет фразы с файлами; `src/content/audio-index.json` обеспечивает поиск файла по неизменяемому идентификатору строки. Оба варианта письменности используют одно и то же аудио. Плеер не требует микрофона и запускает запись после клика. `sr-RS` SpeechSynthesis — резервная опция; чужой голос как сербский не подставляется.

**Ограничение:** eSpeak — роботизированный голос; дорожки не проходили проверки носителем (ударения, č/ć, đ/dž, качество диалогов). Для полностью выверенной программы нужно заменить их проверенными лицензированными нейросинтетическими или человеческими записями и отметить `reviewStatus` в manifest только после проверки. До коммерческой публикации самостоятельно проверить условия лицензии/использования выбранного голоса и источника. Стандарты аудио в исходном ТЗ приведены в `docs/TZ-v2.1-original.md`.

Проверить комплектность и выборочное декодирование:

```powershell
python scripts/check-audio.py
```

Для качественной перегенерации через Azure Speech см. `scripts/azure-tts.py` (потребуются собственные `AZURE_SPEECH_KEY` и `AZURE_SPEECH_REGION`, возможны расходы и условия использования).

## 7. Проверки

```powershell

npm run audio:verify     # Содержимое и декодирование MP3 (нужны Python и ffprobe)
npm run typecheck        # Нужны npm install
npm run test             # Unit-проверки логики доступа
npm run build            # TypeScript + production сборка
```

**Важно:** исходный код был создан и структурно проверен в среде без доступа к npm registry и без учётной записи Supabase. Поэтому здесь не выполнялись реальная установка зависимостей, production `npm run build`, взаимодействие с живой БД, проверка писем, RLS между реальными пользователями и настоящие E2E на опубликованном сайте. Эти тесты обязательны после подключения сервисов.

## 9. Правила сохранения

Зачёт урока и экзамена вычисляется только серверной функцией. Попытки имеют уникальные UUID; повторная отправка не удваивает историю. Ошибка повторного теста не снимает ранее подтверждённый зачёт. После входа на новом устройстве профиль, результаты экзаменов, карточки и последние шаги загружаются из БД. Без сети попытка урока находится в очереди IndexedDB, но **не открывает следующий урок**, пока сервер не подтвердит результат. Полнофункциональный офлайн-режим, админ-панель и ИИ-проверка речи остаются задачами следующих версий.

Старый `localStorage` на другом домене нельзя прочесть автоматически: используй экспорт JSON из старой версии и импорт через настройки нового приложения. Неподписанные старые зачёты хранятся отдельно, не обходя серверную последовательность.
