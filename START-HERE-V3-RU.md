# SrpskiLab v3 — установка учебной редакции (Windows + Supabase + Cloudflare)

**Прочти перед SQL!** Это технически интегрируемая редакция всех 265 уроков, но **не сертифицированный и не лингвистически выверенный курс A0–B2**. В ней 20 подробных авторских черновиков A0 и 245 расширенных учебных карточек на основе прежней теории со специально написанными двухрепликовыми диалогами, тренировкой письма, аудированием и новыми внутренними тестами. Для полноценного 30–45-минутного независимого занятия на B1–B2 нужны дополнительная авторская теория, более длительные тексты, аудирование, свободные продуктивные задания и проверка преподавателем. Не следует выдавать эту версию за полностью завершённый педагогический курс.

**Что реально работает по реализации:** основной маршрут `/lesson/m1l1` … `/lesson/m31l10`, учебная цель, тема, слова, авторский диалог, индивидуальная звуковая запись реплик, независимое аудирование, пять самооцениваемых заданий, письменное/устное самостоятельное упражнение, отдельный тест из 7 вопросов, серверная проверка через Supabase RPC v3 после SQL-активации, прежние аккаунты и история результатов. Старые внутренние экзамены из v2.1 оставлены без новой педагогической экспертизы. Озвучка — синтетическая eSpeak-sr, её качество и права на публичное распространение не подтверждены.

## 0. Не рискуй рабочими данными

- **НЕ запускай повторно** старые `202609290001_schema.sql`, `202609290002_seed.sql` в уже действующем Supabase.
- Не чисти `lesson_progress`, `lesson_attempts`, `exam_attempts`, `auth.users`, `word_registry`.
- Проверь резервное копирование БД и при необходимости сделай отдельный экспорт данных. Разверни **тестовый проект Supabase**, убедись, что изменения срабатывают на копии данных и не обнуляют чужой прогресс.
- Не загружай приватный SQL-файл ответов в GitHub/Cloudflare/папку `src` или `public`.
- Не публикуй новые неподтверждённые синтетические записи для широкой аудитории, пока не проверены условия использования eSpeak и произношение специалистом.

## 1. VS Code: локальная проверка

1. Распакуй полный архив в НОВУЮ папку `C:\Users\User\Desktop\srpskilab-v3`, не затирая оригинал. Архив не содержит `.env.local`, `node_modules` и Git-истории.
2. Открой папку в VS Code. Создай `.env.local` с действующими **публичными** параметрами, которые можно получить в Supabase: `VITE_SUPABASE_URL=https://<твой проект>.supabase.co` и `VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...`. НИКОГДА не добавляй секретный/service_role ключ в Vite.
3. Запусти:

```powershell
npm ci
npm run typecheck
npm run content:v3:verify
npm run test
npm run build
npm run dev
```

4. Пока новая DB-функция ещё не активирована, можно открыть и читать уроки в интерфейсе, но **новый контрольный тест НЕ отправляй** — сервер вернёт ошибку об отсутствии/неактивированной v3-функции.
5. Убедись, что `http://localhost:5173/lesson/m1l1` доступен после входа и в первом уроке представлены слова латиницей и кириллицей. Уроки открываются последовательно — это нормально.
6. Если `npm ci` не работает из-за сети, проверь интернет, версию Node.js (рекомендуется 22+) и что открыт корень с `package.json`. Не запускай `npm run build`, пока есть ошибки TypeScript.

```sql
SELECT count(*) AS course_lessons FROM public.course_lessons;

```

Для исходной установки обычно ожидались **265 уроков, 714 слов, 1855 старых ответов и 100 экзаменационных ответов** (пользовательских строк может быть любое число). Если эти числа отличаются, **не выполняй следующие шаги вслепую**: изучи уже применённые изменения.

## 3. Supabase: миграции в точном порядке

Прежде чем запускать в production, повтори всё в копии Supabase и проверь минимум два тестовых аккаунта. Строго по порядку:

**SQL-1 — создать новые столбец, таблицу/RPC и новые записи словаря.** В Supabase SQL Editor открой и целиком выполни:

`supabase/migrations/202609300001_v3_bank_rpc.sql`

Эта миграция не удаляет старый `private.lesson_question_bank`, создаёт новую `private.lesson_question_bank_v3` и серверную функцию `public.submit_lesson_attempt_v3`. Также добавляет **55 новых A0 слов** в `public.word_registry`, не перезаписывая существующие. Если раньше было ровно 714 слов, станет **769**. Никакие прежние оценки не трогает. Временная колонка `study_content_version` до активации равна 1.

**SQL-2 — заполнить ПРИВАТНЫЙ банк ответов.** Открой ОТДЕЛЬНО скачанный файл `SrpskiLab-v3-answer-bank-PRIVATE.sql` и целиком выполни в SQL Editor. **Не добавляй в проект / GitHub**. Файл защищён проверками: в БД должны быть 265 уроков, банк v3 должен быть пуст, новая версия ещё не активирована. После загрузки:

```sql
SELECT count(*) AS v3_lesson_answers
FROM private.lesson_question_bank_v3;
-- 1855
```

**SQL-3 — только ПОСЛЕ проверки банка переключить версию.** Файл намеренно лежит в `supabase/manual`, а не в автоматических `migrations`: иначе Supabase CLI может применить его до загрузки приватных ответов. Выполни:

`supabase/manual/202609300002_v3_activate.sql`

Его защита требует 265 уроков, 1855 ответов, ровно 7 ответов на каждый урок и версию каждого ответа `2`. Только после этого `study_content_version` становится 2 и новая функция начинает принимать ответы. Старые `content_version` базовых записей, предыдущие попытки и старый RPC сохраняются.

Проверь:

```sql
SELECT study_content_version, count(*)
FROM public.course_lessons GROUP BY study_content_version;
-- study_content_version = 2, 265 записей

SELECT count(*) FROM private.lesson_question_bank_v3;
-- 1855

SELECT count(*) FROM public.word_registry;
-- 769, если исходная база совпадала с 714 и все новые IDs отсутствовали
```

**НИКОГДА не запускай приватный SQL повторно после активации.** Он завершается ошибкой по предохранителю. При этом в текущих файлах DB не применяется никакой массовый UPDATE пользовательского прогресса.

## 4. Проверь сервер перед публикацией

Используй **два созданных тобой тестовых аккаунта** A и B (не чужие аккаунты!). Проверь на ТЕСТОВОЙ базе:

1. Под A открой `/lesson/m1l1`, пройди 7 новых вопросов. Для успешного зачёта нужны **5 правильных из 7** (≈71%, порог 70%). Четыре из семи ≈57%, зачёта не дают.
2. После зачёта убедись, что m1l2 открывается; обнови страницу и выйди/войди. Результат сохранился.
3. На другом устройстве под аккаунтом A виден тот же прогресс. Под аккаунтом B прогресс A НЕ виден. RLS и прямые запросы под токеном B не дают читать личные таблицы A.
4. Под A пересдай уже пройденный урок хуже: `best_score` не должен уменьшиться, `completed` не должен исчезнуть.
5. Нажатие отправки одного `attempt_key` дважды не должно создавать две попытки.
6. Старые результаты v2.1 на копии БД должны оставаться целыми.
7. На границе уровня прежний экзамен содержит 20 вопросов, для зачёта нужно 16/20 (80%); тесты v3 этих экзаменов **не заменяют**.
8. В режиме offline новая попытка должна остаться в очереди IndexedDB и после возврата сети пройти через `submit_lesson_attempt_v3`. Старые уже ожидающие попытки v2.1 сохраняют свой маршрут `submit_lesson_attempt`. Поэтому старый RPC после выпуска ещё доступен для совместимости: он также может зачесть прежние вопросы. Строгий режим «только новый банк» потребует отдельно согласованного отключения старого маршрута после обработки офлайн-очередей.

Ни одна из этих интеграционных проверок не была проведена на твоей реальной Supabase-базе автоматически; их нужно сделать перед публичным запуском.

## 5. GitHub и Cloudflare

1. Сохрани рабочую версию оригинала и используй новую ветку. Если нужно продолжать через свой старый Git-репозиторий, **не заменяй папку `.git` из ZIP**: скопируй новые исходники (не секретный SQL) в рабочую папку, создай ветку `feature/study-v3`.
2. Проверь `git status`: файлов `.env.local` и `supabase/private/` среди новых файлов быть не должно. Правила `.gitignore` их исключают.
3. Сделай локальную сборку `npm run build` и проверь личные маршруты.
4. Сделай `git add .`, `git commit -m "feat: integrate 265 v3 study units"`, `git push -u origin feature/study-v3`.
5. Проверь, что в Cloudflare Workers всё ещё установлены BUILD-переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Наличие только Runtime Variables недостаточно для сборки Vite.
6. После проверки копии БД, лицензии аудио и преподавательского контента внедри миграции в рабочую Supabase. Затем опубликуй именно одобренную ветку (обычно через merge/PR в main). Build command `npm run build`, deploy `npx wrangler deploy`, output assets `./dist` из `wrangler.jsonc`.
7. Проверь `Authentication → URL Configuration` в Supabase: публичный `Site URL` и разрешённые `/auth/callback`, `/auth/reset-password` должны вести на действительный `*.workers.dev`/собственный домен.
8. Протестируй регистрацию, письмо, сброс пароля, первый урок, работу синтезированного аудио, доступ закрытых уроков, облачную синхронизацию, словарь и внутренний экзамен на двух тестовых аккаунтах.

## 6. Что НЕ надо менять вручную

- Не нужно создавать новый проект Supabase, если существующий уже правильно работает.
- Не нужно заново загружать 265 базовых записей и 714 исходных слов старым seed SQL.
- Не нужно перезапускать первоначальную миграцию `202609290001_schema.sql`.
- Не нужно переносить `auth.users` и пользовательские результаты вручную.
- Не нужно создавать Cloudflare D1: эта версия продолжает использовать Supabase PostgreSQL.
- Не нужно регистрировать второй домен для локальных учебных страниц; это обычные маршруты SPA.

## 7. Откат без потери прежних результатов

Если в новой версии есть критическая проблема, верни **старый frontend-релиз Cloudflare** (предыдущую Git-версию), который вызывает старый RPC `submit_lesson_attempt`; старая таблица ответов не менялась. Не делай DELETE из `lesson_progress` или таблиц с попытками. Новая таблица и столбец останутся в DB, но не мешают старому коду. **Реальная проверка отката должна быть проведена на тестовой базе.**

## 8. Незакрытые вопросы перед публичным образовательным релизом

- 245 уроков A1–B2 ещё требуют расширения авторской теории, более продолжительных диалогов и аудирования по стандарту ТЗ v3.0; текущие диалоги обычно двухрепликовые.
- Все новые тексты и синтетическая фонетика требуют независимой проверки преподавателем сербского. Никакая автоматическая сборка не удостоверяет грамотность языка.
- Лицензия и условия распространения синтетических MP3 должны быть проверены отдельно.
- Внутренние экзамены по уровням не переписаны, не оценивают живую устную речь и не заменяют официальную сертификацию CEFR.
- Самостоятельное письмо и говорение в обычном уроке не оцениваются автоматически и пока не синхронизируются как отдельные черновики.
- Production DB и настройки Cloudflare из этого архива недоступны автору этих изменений; сквозной E2E в реальном аккаунте необходимо провести самостоятельно.

**Если твоя цель — полноценный, педагогически проверенный курс B2, не считай этот релиз завершением ТЗ v3.0.** Это интегрированная учебная редакция с 265 доступными материалами для самостоятельной практики и новыми техническими тестами.
